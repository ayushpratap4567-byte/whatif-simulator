# What If Simulator

A Dr. Stone–themed "What If" scenario simulator. Black background, glowing
green terminal UI, and answers generated by Gemini — with **live Google
Search grounding** enabled server-side, so it can pull in real, current
facts instead of relying only on the model's training data.

## How it's structured

```
whatif-app/
├── api/
│   └── simulate.js     ← serverless function, holds your API key, calls Gemini
├── public/
│   └── index.html      ← the frontend (static, no build step)
├── package.json
├── .env.example
└── .gitignore
```

The browser never talks to Google directly. It calls `/api/simulate` on
your own domain, and that serverless function (running on Vercel's servers,
not the user's browser) makes the real Gemini API call with your secret
key attached. This is the only safe way to do this — a key placed in
frontend JS is visible to anyone who opens dev tools.

## Deploy it (Vercel — free tier works)

1. **Get a Gemini API key (free)**
   Go to [aistudio.google.com/apikey](https://aistudio.google.com/apikey),
   sign in with your Google account, and click **Create API key**. The free
   tier is enough to run this project — no billing setup required to start.

2. **Create a GitHub repo and push this folder to it**
   ```bash
   cd whatif-app
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/whatif-simulator.git
   git push -u origin main
   ```

3. **Import the repo into Vercel**
   - Go to [vercel.com/new](https://vercel.com/new)
   - Select your GitHub repo
   - Vercel will auto-detect it (static `public/` + `api/` functions need no
     special build settings)

4. **Add your API key as an environment variable**
   - In the Vercel project → **Settings → Environment Variables**
   - Add `GEMINI_API_KEY` = your key from step 1
   - Redeploy (Vercel prompts you, or push a new commit)

5. **Done** — Vercel gives you a live URL like `whatif-simulator.vercel.app`.

## Run it locally first (optional but recommended)

```bash
npm install -g vercel
cd whatif-app
cp .env.example .env      # then paste your real key into .env
vercel dev
```

This starts a local server (usually `http://localhost:3000`) that runs the
serverless function exactly as it will run in production.

## Alternatives to Vercel

The `api/simulate.js` function uses the standard Vercel serverless function
signature (`export default function handler(req, res)`). If you'd rather
use **Netlify** or a plain **Node/Express** server instead, say so and I can
adapt this file — the core logic (the Gemini call with search grounding)
stays identical, only the request/response wrapper changes.

## Cost note

The Gemini free tier has generous but real rate limits (requests per
minute/day). Search grounding itself has its own daily free quota (currently
large — see [ai.google.dev/pricing](https://ai.google.dev/gemini-api/docs/pricing)
for current numbers, since these change). For a personal/demo project you're
very unlikely to hit limits, but if you plan to share the link publicly, it's
worth checking your usage in [aistudio.google.com](https://aistudio.google.com)
occasionally. I can add basic rate-limiting (e.g. max N requests per IP per
hour) if you want a safety net before sharing it widely.
